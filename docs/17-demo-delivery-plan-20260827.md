# ForestBridge 3.5 天可交付 Demo 计划（2026-08-27）

## 交付目标与冻结范围

在剩余约 3.5 个实验日、每天 4–5 小时内，交付一个可由手机网页发起和观察的固定场景 Demo：机器人从已验收起点定位，导航到已验收桌边停靠点，执行现有 ACT 面霜抓取/局部放置，并在网页显示当前状态、最近画面、结果和失败原因。操作员只负责一次任务启动和随时可用的紧急停止；普通阶段切换不再要求反复输入 `RETURN`、`PLAN`、`MOVE`、`READY`。

本轮不把“携物导航到第二工作站”、任意物体抓取、动态避障、人体动作映射和开放式 LM 自主规划列为必须交付。它们只能在固定闭环连续通过后作为加分项。现有受监督脚本全部保留，作为诊断与回退入口。

## 系统边界

- **Jetson 本地**：独占 USB、ROS、摄像头和电机；运行确定性任务执行器、安全检查、超时、刹车与有限恢复。断网或网页失联必须本地停止，不能依赖公网服务器完成急停。
- **Frankfurt 服务器**：提供 HTTPS 手机网页、任务/状态中继和演示日志。它不直接写舵机，也不持有绕过 Jetson 安全门的接口。
- **手机网页**：提交白名单任务、显示状态和低频快照，提供普通 Stop；物理 12 V 切断仍是最终急停。
- **LM/语音**：最后接入，只允许把自然语言转换为白名单 `TaskSpec`，不能产生轮速、关节角或任意 shell 命令。

## 时间表

### 第 1 天：任务执行器与可观察状态（4–5 h）

1. 固定 `navigate_then_pick_place` 的状态、输入、输出和失败语义。
2. 输出原子 `status.json` 和追加式 `events.jsonl`，支持本地 Stop 和有限重试。
3. 用离线 dry-run 验证完成、重试、不确定结果和停止路径；不接触硬件。
4. 只读体检 Frankfurt，确定部署方式和资源约束。

完成标准：网页端未来无需解析终端文本即可知道机器人处于哪一步；离线测试覆盖所有终止路径。

### 第 2 天：本地网页闭环，先接假机器人（4–5 h）

1. 建立最小 API：创建一个白名单任务、读取状态/事件、请求 Stop、读取最新相机快照。
2. 建立手机页面：Start、Stop、状态时间线、最近画面、任务结果。
3. Frankfurt 部署 HTTPS 前端/中继；Jetson 只通过出站连接拉取任务并上报状态。
4. 先用 dry-run 完整演示手机发起任务，不允许真实运动。

完成标准：手机可看到一个完整假任务从 `precheck` 走到 `complete`，Stop 可中断，断开中继不会触发任何硬件动作。

### 第 3 天：连接现有真实管线并做三次受控实验（4–5 h）

1. 为现有 Gemini、Nav2、ACT 脚本增加非交互但仍受授权令牌约束的适配层；保留旧交互入口。
2. 任务启动前一次性完成云台、总线、停机能力、地图版本和工作区检查。
3. 现场先做短距离导航，再做导航到桌边，最后做一次完整导航→ACT。
4. 每次保存统一 task ID 下的导航目录、ACT 日志、事件流和操作员结果。

完成标准：至少 3 次受控端到端运行中，安全停止 3/3；争取完整成功 2/3。失败必须能在网页明确显示在哪一阶段、是否可重试。

### 最后半天：固化、录像与交接（2–3 h）

1. 冻结地图、停靠点、物体摆放模板和已验证命令。
2. 录制一次成功 Demo 和一次失败后安全停止/恢复 Demo。
3. 写一页操作手册与队友接管清单，备份模型、地图、日志和版本号。
4. 若仍有余量，只加入“语音/文本选择固定任务”，不扩展新的运动能力。

## 当前第一步

`tools/forestbridge_task_executive.py` 是第一版网页任务契约，当前刻意只支持 dry-run。状态顺序为：预检、建图相机位、定位、规划、导航、停靠验证、抓取相机位、抓取、结果验证、完成。每一步返回 `success`、`retryable_failure`、`fatal_failure` 或 `uncertain`；未知结果进入人工协助，不能继续运动。下一步是在不改变旧脚本的前提下，为每个已验证技能增加 Jetson 本地适配器。

## Frankfurt 体检结论

2026-08-27 只读检查确认该主机为 Debian x86_64，已有 Docker、Node 和 Python，根盘约 25 GB 可用；内存仅约 3.6 GiB，检查时可用内存很低且 Tailscale 未运行。因此它适合轻量网页/API/事件中继，不适合运行视觉模型、SLAM 或视频转码。第一版画面采用低频 JPEG 快照，暂不做持续高清视频。正式部署前还要确认域名、TLS、认证和服务端已有负载。
