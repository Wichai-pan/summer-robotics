## 1. 目的

固定视角的 IK、ACT 和即将开展的 SLAM 需要共享同一个可恢复的 Gemini 云台参考状态。本轮完成三件事：

1. 确认两个云台舵机的物理轴与方向；
2. 在松扭矩状态人工读取左右、上下活动端点；
3. 验证云台能够低速回到保存的抓取视角。

本轮没有修改舵机 EEPROM、硬件角度限位或 `homing_offset`。手动端点文件是安装状态记录，不是已经接入控制器的硬限位。

### 3.2 yaw 的解释

ID 7 是循环编码器，`4095 -> 0` 是同一个圆周上的相邻位置。程序输出的 `relative_to_grasp_deg` 使用编码器最短差，因此超过或接近 180° 时会折返，不能单独用其正负号判断操作者实际选择了左转还是右转。

现场观察表明：

- 按操作者实际选择的连续转动方向解释，向左端点约为 `196.44°`，说明左侧可超过 180°；
- 按操作者实际选择的连续转动方向解释，向右端点约为 `181.58°`，且已接近现场选择的安全端点；
- 当前阶段不需要利用超过 180° 的额外行程。

给第一版 SLAM/观察控制的约定：

- 常规自动运动建议限制为参考位两侧 `±175°`；
- 确实需要观察正后方时，可低速放宽到 `±179°`；
- 不使用正好 `180°`，避免最短路径无法唯一决定向左还是向右；
- 若未来需要连续越过 180°，必须额外维护累计角度和指定旋转方向，不能只给一个最终 raw。

这里的 `±175°/±179°` 是给后续 SLAM 云台控制的暂定设计范围，并不是当前脚本已经实施的软件限位。现有 `return` 默认最大自动行程为 `120°`；本次回正之所以通过，是因为采集 pitch 端点时 yaw 已被人工带回 `raw=4049` 附近。未来若要从 yaw `±179°` 直接自动回正，需要另外验证并批准扩大 `--max-travel-deg`，或实现分段、有明确方向的回正，不能直接假定当前默认命令可以完成。

### 3.3 pitch 的解释

当前抓取参考视角本身已经明显朝下，因此实测可抬头约 88°，继续低头只有约 6°。这符合现场机械状态，不表示 ID 8 读取异常。

## 4. 回正测试

完成手动端点记录后，云台停在最后的低头位置。使用：

```bash
cd /home/jetsonl7/summer-robotics-deploy

./scripts/jetson_robot_exec.sh \
  --black --interactive -- \
  python3 tools/gemini_gimbal_pose.py return --execute
```

输入 `RETURN` 后的计划与结果：

| 项目 | ID 7 | ID 8 |
|---|---:|---:|
| 回正前 raw | 4049 | 2354 |
| 目标 raw | 4062 | 2284 |
| 计划最短位移 | +1.14° | -6.15° |
| 回正后 raw | 4057 | 2287 |
| 相对目标残差 | -0.44° | +0.26° |

程序报告 `status=PASS`，并确认两个舵机均恢复位置模式 `mode=0`、松扭矩 `torque=0`。回正误差处于脚本的 0.5°验收范围内。

## 5. 给 SLAM 集成的约束

1. 固定视角静止视觉里程计或建图前，先运行 `return --execute`。
2. 回正后，在该次静态 TF/SLAM 运行期间不要手动移动云台。
3. 若 SLAM 主动控制云台，需要发布/维护随 ID 7/8 变化的动态相机外参；固定 `base_link -> camera_link` 与运动云台不能同时成立。
4. `manual_limits_v1.json` 目前用于记录和规划，不代表控制器已经自动执行端点保护。
5. 原始 raw 和方向标签是权威证据；`one-turn` 与最短相对角不是世界坐标系中的绝对 yaw/pitch。
