# 实验记录 06 · RGB-D 桌面物体定位与黑臂抓取准备

- **日期**：2026-08-03
- **平台**：Mac（Apple Silicon）+ Orbbec Gemini 335 + XLeRobot 黑色 SO-101 臂
- **任务**：用固定朝下的头部 RGB-D 相机定位桌面浅蓝色面霜罐，并确认黑臂可在当前桌边停靠位完成抓取。
- **状态**：✅ 感知已验证；✅ 人工键盘遥操作抓取成功；✅ 受监督固定轨迹已完成真实拿起与放回；⏳ 尚未实现相机坐标驱动的自动抓取。

## 1. RGB-D 感知验证

在 `simtoreal` 分支的 `cameratest/` 中，以 Gemini 335 官方 SDK 的 RGB 与对齐深度流进行颜色分割和鲁棒深度估计。浅蓝色矮圆柱面霜罐在灰色窗帘等相似背景存在时，加入桌面 ROI 后稳定定位；纯蓝色目标不是本次验证的必要条件。

本次居中放置面霜罐的稳定观测示例：

| 输出 | 数值 | 含义 |
|---|---:|---|
| center x (right) | +2.1 mm | 相对相机光轴向右 |
| center y (down) | +15.0 mm | 相对相机光轴向下 |
| center z (forward) | +477.9 mm | 相对相机光轴前方 |
| range | 477.2 mm | 相机到目标表面的直线距离 |
| confidence | 0.93 | 当前颜色/深度观测置信度 |
| depth MAD | 6.0 mm | 深度块内部离散度，越小越稳定 |

`x/y/z` 都是**相机光学坐标系**：相机向下俯视时，`y down` 不等于世界坐标的高度。后续必须求得相机到黑臂基座的刚体变换 `T_base_camera`，才能把该点用于机械臂控制。

## 2. 黑臂可达性与抓取验证

- 移动底盘置物架已贴住桌边；目标位于黑臂可达范围内。
- 使用已验证的 [`tools/arm_keyboard.py`](../tools/arm_keyboard.py) 控制黑臂（`python tools/arm_keyboard.py black`，复用 `black_arm.json` 标定）。
- 已人工完成“靠近 → 对准 → 合爪 → 抬起”一次，确认当前黑臂、夹爪和桌边停靠关系可完成该物体的抓取。

这不是自动抓取结果：动作是键盘遥操作完成的，且该脚本启动后会归零，因此每次运行前须清空机械臂周围区域。

### 已录制固定轨迹

2026-08-05 已通过黑臂键盘控制记录四个控制器关键帧：`pregrasp_open` → `descend_open` → `close_gripper` → `lift`。它们已写入 [`tools/black_arm_facecream_replay.py`](../tools/black_arm_facecream_replay.py)，该脚本逐阶段请求 `MOVE` 确认、低速插值并可选择受监督放回；只适用于本记录中的固定桌边场景。

**真实硬件结果（2026-08-05）**：该回放已在固定场景中完成一次完整的“回零 → 预抓取 → 下探 → 合爪 → 抬起 → 放回 → 退回”流程。每个阶段均由现场人工输入 `MOVE` 放行；没有发生碰撞。该结果证明录制的控制器关键帧可被同一控制器低速复用，但不等同于任意物体位置的自主抓取。

## 3. 已识别的边界

- 小物体的颜色分割容易受背景、阴影和物体尺寸影响；当前以固定面霜罐和固定桌面 ROI 做窄任务验证。
- YOLO/通用类别检测可作为后续替换方案，但本次不需要先解决开放类别小物体检测。
- 相机位置、俯仰角和底盘停靠位必须固定；一旦移动头部云台或底盘，外参需要重新检查。

## 4. 2026-08-06 · Sim-to-real 解析 IK 首次验证

在 `simtoreal` 分支代码的基础上，已将浅蓝色面霜罐的颜色分割限制到桌面 ROI `(80, 80, 500, 440)`，并以 10 帧 RGB-D 观测生成稳定的物体光学坐标。一次实测的最大三维散布为 **1.33 mm**，说明当前 Gemini 感知足以作为标定输入。

用 XLeRobot URDF 的黑色左臂镜像根节点、相机安装初值和官方两连杆解析 IK 生成了高位预抓取计划。该计划通过了标称臂展检查，但在真实黑臂上进行一次**只到高位、不下探、不闭爪**的受监督测试时，机械臂主要抬起和张开，未停在面霜正上方，且 P 控制插值存在明显顿挫。

结论必须明确：

- ✅ RGB-D 目标检测与深度稳定性已验证；
- ✅ 黑臂键盘控制和固定轨迹抓取已验证；
- ❌ **不能将仿真 IK 的绝对关节角直接当作真实黑臂 P 控制目标**；真实相机外参、机械臂零位/方向和工具偏移尚未被标定；
- ❌ 不应把单次人工成功姿态当成“自动抓取策略”或以局部姿态记忆替代标定。

本次试验没有发生桌面碰撞或下探；机械臂已在测试结束后松扭矩。后续不复用该绝对 IK 执行结果。

### 下一阶段：计算式而非记忆式标定

目标是固定相机的 **eye-to-hand（相机—机械臂）标定**，而不是记录物体位置对应的抓取动作。保持底盘、头部云台和桌面不动，在夹爪固定一个 Gemini 可稳定识别的彩色标记（可先夹住面霜作为标记），采集 6–10 个安全且分散的姿态。每个样本包含：

1. 黑臂 `MEASURED_ENCODER_JSON` 实测关节角（`SAVED_TARGET_JSON` 仅用于诊断旧 P 控制器映射）；
2. Gemini RGB-D 观察到的标记三维坐标。

用这些对应关系拟合真实的 `T_base_camera`、关节零位偏差和末端工具偏移。拟合通过独立验证后，才重新启用“物体 RGB-D 坐标 → 基座坐标 → 解析 IK → 分阶段抓取”的计算链路，并改用平滑轨迹执行。

## 5. 下一步：从“能看见、能手抓”到自动抓取

1. 固定 Gemini 云台、黑臂基座、桌边停靠位；采集 6–10 组夹爪标记的 RGB-D/关节对应样本。
2. 拟合并留出独立样本验证 `T_base_camera`、关节零位和工具偏移；验证失败时不得发送自动动作。
3. 定义安全抓取状态机：预抓取点 → 垂直下降 → 合爪 → 抬升；每段保留可中止和人工监督。
4. 接入标定后的真实逆运动学、关节限位和平滑轨迹执行，再用同一物体重复验证。
5. 在确定性闭环稳定后，再采集遥操作示范数据并训练 ACT / VLA 基线。

## 6. 2026-08-07 · 九点 eye-to-hand 离线拟合

已采集 9 组黑臂实测编码器角度与 Gemini 标记三维坐标，覆盖相机坐标约 X `158 mm`、Y `63 mm`、Z `208 mm`；五个关节的实测角度范围分别达到 `35° / 37° / 52° / 141° / 115°`。RGB-D 单组最大散布为 `3.55 mm`。

[`tools/fit_black_arm_eye_to_hand.py`](../tools/fit_black_arm_eye_to_hand.py) 动态读取 XLeRobot URDF 黑臂链，枚举关节方向，并拟合可辨识的关节零点、夹爪内标记点和相机刚体外参。它是纯离线程序，产物强制标记为 `motion_locked`。合成真值单元测试已通过，确认正运动学、刚体配准和优化实现可恢复一致数据中的几何模型。

真实数据采用前 8 组训练、第 9 组完全留出，结果为：

| 指标 | 结果 |
|---|---:|
| 训练点 RMSE | 10.64 mm |
| 留出第 7 组误差（诊断） | 14.98 mm |
| 留出第 8 组误差（诊断） | 20.80 mm |
| 留出第 9 组误差 | **93.41 mm** |

本轮结论是 **FAIL，不得用于真实 IK**。第 9 组在约相同 19 cm 深度处选择出的蓝色区域为 `137×202 / 8211 px`，而第 8 组只有 `20×12 / 110 px`；两者明显不是稳定一致的物理特征点。退出控制器松扭矩后，面霜也可能相对夹爪发生滑动或被重新夹持。面霜表面的“蓝色区域三维质心”会随遮挡和观察方向移动，因此不满足 eye-to-hand 标定要求的刚性固定点假设。

拟合产物 [`calibration/black_arm_eye_to_hand_fit.json`](../calibration/black_arm_eye_to_hand_fit.json) 仅保留失败证据和诊断信息，不能复制到执行配置。下一轮应将小型 ArUco/AprilTag 板或明确的固定点标记刚性安装在夹爪上，并在一次不断电、不松夹的采集会话中重新采点；随后再运行同一离线拟合器进行独立留出验证。

复现命令：

```bash
conda activate lerobot
python tools/fit_black_arm_eye_to_hand.py --starts 10
python tests/test_eye_to_hand_fit.py
```
