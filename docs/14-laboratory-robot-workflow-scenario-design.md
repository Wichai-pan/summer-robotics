# 面向真实实验室环境的 XLeRobot 机器人工作流场景设计

本文在现有 XLeRobot 项目成果的基础上，设计一个面向真实实验室环境的机器人应用场景。设计重点不是展示单一的抓取、导航或人机交互功能，而是将这些能力组织成一套符合实验室工作特点、能够被监督和验证的完整工作流。

## Motivation

### 1. 面向实验室环境的真实需求

化学、生物和材料实验室中存在大量结构化但重复的工作，例如按固定顺序取放试剂、转移容器、准备实验器材、在工作台之间运送样品，以及在实验结束后回收和归位物品。这些任务通常步骤明确、重复频率高，会持续占用实验人员的时间，也容易因为疲劳或操作不一致产生误差。

与此同时，实验室并不是普通的家庭或仓储环境。机器人可能需要面对玻璃器皿、液体、化学试剂、精密仪器、狭窄通道和多人共享的工作空间。部分物品易碎、具有污染风险或对放置姿态有严格要求；部分设备只能按照规定的顺序和力度操作。因此，实验室机器人不仅要“能够完成动作”，还必须具备较高的操作精度、过程可追踪性和明确的安全边界。

### 2. 让机器人代替人员进入操作区域

本项目希望在 XLeRobot 的基础上建立一种人与实验操作区适度隔离的工作方式。实验人员负责提出任务、示范流程、确认关键步骤并处理异常，机器人负责进入指定区域，与实验设备和物品进行交互。这样可以减少人员在重复任务或潜在危险环境中的直接暴露，同时保留人的专业判断和最终控制权。同时这种隔离还是一种让科学家远程操作和高效控制实验的方法：为未来的实验方式提出一种充满想象力的设想。


### 3. 从单项能力发展为完整工作流

在实验室的复杂环境和执行实验的复杂过程中，要求机器人将其具有的各项单项能力（比如导航，抓夹等等）中选择合适的工具，结合机器人的干重能力实现工作流完成任务。

以“按实验流程准备一组试剂”为例，机器人需要先理解或接收任务，检查目标物品和工作区域是否符合条件，移动到储物区域，识别并拿取指定容器，将其运送到目标工作台，再按照经过验证的动作流程进行摆放或操作。执行过程中，实验人员应能通过指令或手势确认、暂停、纠正或终止任务。任务结束后，机器人还需要记录执行过程并回到安全状态。

## Method

### 1. 重复实验任务的操作方法

针对试剂准备、容器搬运、器材摆放等重复任务，我们并行采用模仿学习和传统机器人控制编程两种方法。两种方法各有优劣，我们可以根据任务特点组合使用。（这里也可以变成模仿学习更好，分析它相比于传统机器人控制编程的一些优点）

#### 1.1 模仿学习

对于轨迹复杂、难以完全用规则描述，但可以由实验人员反复示范的操作，使用 LeRobot 数据采集和 ACT 模仿学习流程。实验人员通过主从机械臂示范抓取、移动、放置等动作，系统记录机械臂状态和相机图像，并在离线计算资源上训练策略，最终将模型部署到 Jetson 执行。

模仿学习适合处理具有一定视觉和动作变化的操作，例如从限定区域内抓取容器、将物品移动到固定工作位置，或完成一段连续的操作轨迹。但学习策略不能单独承担整个实验流程。它的输出必须受到关节范围、动作速度、工作空间和超时条件的限制；抓取后还需要结合夹爪位置、电流、负载和腕部相机判断是否真正抓稳。若检测到空抓、滑落、卡住或结果不确定，系统应停止转运，并进入有限次数的重试或人工接管流程。

#### 1.2 传统机器人控制编程

对于目标明确、需要确定性和高可解释性的动作，使用传统机器人控制方法。例如机械臂回到折叠姿态、移动到标定点、限制关节速度、夹爪开合、短距离对准、任务超时和紧急停止等，都应由显式程序和状态机执行。

传统控制还承担模仿学习策略前后的安全封装：在策略运行前检查机器人、相机、目标物和工作区状态；在策略运行中限制动作范围并监测反馈；在策略结束后验证结果、释放物品并确定性地回到安全姿态。通过这种方式，学习方法负责难以手工编码的局部操作，传统控制负责流程边界、安全条件和可重复的固定动作。

#### 1.3 任务技能化（也是来自于idea）

每个实验操作被封装为一个经过验证的技能，例如“拿取指定容器”“运送容器”“放置到标定区域”或“返回安全姿态”。每项技能都需要定义：

- 允许操作的物品、起点和目标区域；
- 执行前必须满足的条件；
- 使用模仿学习、传统控制或二者组合的具体方式（也可以只用模仿学习hhh）；
- 运行中的速度、范围、超时和反馈限制；
- 成功、失败和结果不确定的判断标准；
- 失败后的停止、重试、恢复或人工接管方式。

对于试剂调配等具有接触、液体或污染风险的任务，第一阶段不直接追求完整自动化，而是从封闭容器的识别、搬运和排序开始。开盖、移液、倾倒和设备按钮操作必须在完成专用末端工具、精度评估、污染控制和任务风险审查后，才能作为新的独立技能加入工作流。

### 2. 实验室内部的地图重建与移动导航（这部分让ai写的）

移动能力用于连接储物区、机器人等待区和实验工作台，使机械臂操作不局限于一个固定桌面。系统使用 Gemini 335 RGB-D 相机完成实验室环境的地图重建和定位，并结合现有 Nav2 工作流生成机器人在实验室内部的移动路径。

实验室地图不仅描述墙面和通道，还需要标记与任务相关的语义区域，包括允许机器人停靠的位置、机械臂可操作的工作台、试剂或器材存放区、人员通道、禁止进入区域以及紧急停车区域。导航目标不是任意坐标，而是经过测量和验证的停靠点；机器人到达后还需要确认自身姿态是否满足后续机械臂的操作范围。

移动过程采用监督式和分阶段的安全策略：

- 任务开始前确认地图版本、相机姿态和定位状态；
- 只允许前往白名单中的实验室位置；
- 在狭窄通道、人员附近和工作台周围降低速度；
- 持续检查轮组反馈、定位质量、障碍物和通信状态；
- 发现路径被阻挡、定位漂移或底盘反馈异常时立即停止；
- 到达目标后先验证停车位置，再允许机械臂开始操作；
- 地图或实验室布局发生变化后重新验收路线和停靠点。

导航与操作之间必须通过明确的状态交接连接。底盘仍在移动、停车结果未经确认或定位质量不足时，机械臂不得进入实验操作阶段；机械臂没有收回到运输姿态时，底盘也不得开始下一段移动。

### 3. 面向实验室协作的人机交互（这是新idea的）

在人机交互方面，项目在原有机器人操作和导航能力上进一步增加实验人员与机器人之间的协作层。该模块与重复任务执行、地图重建和导航处于同一级别，是机器人适应真实实验室环境的重要组成部分。

系统计划结合语言或图像请求、人体姿态识别和少量确定性手势，让实验人员能够在不进入机器人操作区域的情况下发起和监督任务。第一阶段使用 Gemini RGB-D 图像和 YOLO11n-pose 提取人体关键点，并将连续视觉结果转换为结构化的手势事件，例如请求注意、指向左侧或右侧、取消任务和紧急停止。

人机交互模块不直接输出轮速、电机寄存器值或任意机械臂关节目标。语言模型只能从经过验证的技能白名单中生成高层任务计划；手势识别也必须经过持续时间、置信度、画面时效和单人跟踪检查，然后由确定性的安全监督器决定是否接受。多人输入存在歧义、人体跟踪丢失、图像过期、动作未知或通信失败时，系统默认不执行动作。

在后续阶段，视觉系统还可以生成受限制的上半身镜像目标，用于面对面的动作演示或让实验人员以更自然的方式教授粗粒度动作。但视觉镜像不能直接复制人体关节角度，也不能替代精密的主从臂示教。它必须先明确人体、相机和机器人坐标系之间的关系，并经过工作空间、关节范围、速度和碰撞检查；输出应先在离线回放和可视化界面中验证，再逐步进入单臂、低速、小范围的监督测试。
