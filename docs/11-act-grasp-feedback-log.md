## 3. 45 秒诊断

诊断命令：

```bash
./scripts/jetson_act_trial.sh --label duration45_diag --steps 900
```

日志：

```text
/home/jetsonl7/robot-data/logs/20260811_200200_duration45_diag.log
```

程序完成 900/900 steps，并被现场标记为失败。动作块摘要显示：

1. `0–5 s`：第一次向目标伸出；
2. `5–10 s`：夹爪从约 10 闭合到约 50；
3. `10–20 s`：未夹住，机械臂回收并把夹爪重新张开到约 4；
4. `20–25 s`：第二次伸出并闭合；
5. `25–40 s`：再次回收和调整；
6. `40–45 s`：第三次伸出，最后停在夹取姿态而非固定终点。

这证明更长时间会让当前闭环重新进入类似的抓取周期。当前 ACT 没有终止动作，也没有明确的“物体已夹住”状态；当视觉和关节状态再次类似抓取前状态时，策略可以重新启动抓取。

## 4. 失败归因

### 已排除

- 白臂没有失去通信；
- ACT 推理没有崩溃；
- 两路相机没有触发陈旧帧停止；
- 夹爪确实收到并执行了明显的闭合命令；
- 30 秒不够解释前三次首次夹取失败，45 秒也没有提高成功率。

### 当前主要缺口

1. 抓取中心仍有几毫米级偏差，圆柱面霜可能只接触一侧夹爪；
2. 当前策略观测只有六关节状态、Gemini RGB 和白臂腕部 RGB，没有夹爪电流或负载；
3. 策略无法可靠区分“夹住”“夹空”“接触后滑落”；
4. 11 条固定场景示范足以验证链路，但不足以得到稳定的闭环恢复行为；
5. 多数动作块受到训练范围、命令 slew 或跟踪包络裁剪，可能进一步改变接触阶段的细节时序。

## 5. 明日计划：抓取反馈监督器

暂不直接提高扭矩，也不把运行时间继续扩大。先单独测量白臂夹爪在以下状态的反馈：

1. 完全张开；
2. 空夹闭合；
3. 正确夹住面霜；
4. 夹偏或滑落。

每种状态记录：

```text
Goal_Position
Present_Position
Present_Velocity
Present_Load
Present_Current
```

建立阈值后，把确定性的抓取监督器嵌入 ACT rollout：

```text
ACT 到达并闭合
  -> 位置误差 + 电流/负载确认接触
  -> 小幅抬升 3–5 cm
  -> 白臂腕部相机确认面霜仍在两指之间并随夹爪移动
  -> 成功则保持闭合并继续搬运
  -> 失败则张开、重新对准，最多重试 1–2 次
  -> 卡住/过载则立即停止
```

第一版监督器在 ACT 外部工作，不改变 checkpoint 输入，因此可以使用当前模型快速验证。只有在阈值和流程稳定后，才考虑把电流、负载和抓取状态加入新数据集并重新训练。
